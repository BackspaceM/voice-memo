录音格式

为什么默认 WAV？

浏览器 MediaRecorder 生成的 WebM/M4A 常常缺少时长元数据，首次播放时浏览器算不出长度会静音，播过一次才正常。WAV 自带完整 RIFF 头与时长，且 Windows / macOS / iOS / Android / 车载播放器都能直接打开。代价是体积较大（48kHz 单声道约 5.8 MB/分钟）。

下载

批量导出的 ZIP 始终按原始格式打包，文件名带正确扩展名；详情面板另有「转 WAV 下载」可单独转换任意一条。

容量上限

0 表示不限制（默认）。上传与导出均为流式写盘，大文件不会占满内存；如需给 NAS 留出空间，可在这里随时改，立即生效。

容器运行信息（只读）

PUID / PGID / UMASK 与 HTTPS 开关在进程启动时读取，需在 docker-compose.yml 中修改并重建容器；其余设置都能在本页即时修改。

当前连接

为什么用了 HTTPS 还是不能录音？

浏览器规定 getUserMedia 只能在「受信任的安全源」下使用。自签证书如果没有导入设备信任库，Edge / Chrome 即使让你点了「继续前往」，也会直接隐藏麦克风接口 —— 这与浏览器版本无关，升级到最新版也无效。四条可用路径：

  1. 推荐：内置 HTTPS + 安装 CA —— 在 compose 里加 ENABLE_HTTPS=1、TLS_SAN=你的NAS_IP或域名 重建容器，访问 https://<SAN 里的地址>:端口，再按下方步骤把 CA 装进设备信任库并重启浏览器。地址必须与证书里的地址一致。
  2. 手机最省事：用系统录音机 —— 点「手机录音」调起系统录音 App，录完自动导入。这条路径不依赖麦克风 API，HTTP、自签 HTTPS、任何浏览器都能用。
  3. 桌面 Chrome / Edge 用下方启动参数把 HTTP 地址视为安全源（需独立 user-data-dir）；Firefox 可在 about:config 打开 media.devices.insecure.enabled 与 media.getusermedia.insecure.enabled。
  4. 不录音，改用「导入音频」上传手机 / 录音笔文件，转写、摘要、检索、导出在纯 HTTP 下完全可用。

安装自签 CA（内置 HTTPS 必做）

下载 CA 证书 (.crt) 下载 iOS 描述文件 (.mobileconfig)
  1. Windows：双击 .crt → 「安装证书」→ 存储位置选「本地计算机」→ 放入「受信任的根证书颁发机构」；完成后完全关闭并重启 Edge / Chrome。
  2. macOS：双击 .crt 导入「钥匙串访问」→ 在系统钥匙串中找到 Voice Memo Suite Local CA → 双击 → 信任设为「始终信任」；重启浏览器。
  3. Android：下载 .crt → 设置 → 安全 → 更多安全设置 → 加密与凭据 → 从存储设备安装 → 选择「CA 证书」；安装后用 Chrome / Edge 重新打开页面。
  4. iOS / iPadOS：用 Safari 点「下载 iOS 描述文件」→ 允许下载 → 设置 → 通用 → VPN 与设备管理 → 安装「语音备忘录 本地 CA」；再到 设置 → 通用 → 关于本机 → 证书信任设置，打开对该根证书的完全信任，最后重启 Safari。

装完后地址栏不应再出现「不安全 / 证书无效」。若仍提示不支持，请确认访问地址写在 TLS_SAN 里（IP 与域名都填，逗号分隔），且没有通过反向代理把 HTTPS 换成另一张证书。也可改用 NAS 已有的正式证书（TLS_CERT_FILE / TLS_KEY_FILE）或反代，就不需要装 CA。
